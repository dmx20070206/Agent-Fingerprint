# data/experiments 实验结果分析

[文档导航](README.md) · **历史分析**：本文针对两个 v3 实验（58 维），数字不代表当前 v5 / attribution 的结果。当前运行方式见[训练指南](attribution-training.md)。

分析范围：`l3_v3_agent`、`l3_v3_llm` 两个已保存实验。原始模型、评估文件和运行数据均未修改；补充诊断保存于 [diagnostics.json](../data/results/experiments_review/diagnostics.json)，可用 [reproduce.py](../data/results/experiments_review/reproduce.py) 从仓库根目录复现。

**结论：当前 L3 特征能很强地区分已见实验配置下的框架，但跨任务效果明显下降；LLM 标签有可识别信号，却高度依赖框架、任务和完成情况。现有结果不能证明跨任务的 100% 框架识别，也不能证明框架无关的 LLM 指纹。**

## 1. 原始实验实际测量了什么

两次实验使用完全相同的 78 个运行、58 维 v3 特征和数据集 SHA-256。模型是中位数填补（含缺失指示列）→标准化→逻辑回归，C=1，seed=42，按目标标签分层的 5 折交叉验证。

| 目标 | 类别数 | 折外正确数 | Accuracy | Macro-F1 | 多数类基线 Accuracy |
|---|---:|---:|---:|---:|---:|
| Agent 框架 | 5 | 78/78 | 100.00% | 1.0000 | 24.36% |
| LLM 标签 | 3 | 62/78 | 79.49% | 0.7691 | 38.46% |

来源：[Agent 原始评估](../data/experiments/l3_v3_agent/evaluation.json)、[LLM 原始评估](../data/experiments/l3_v3_llm/evaluation.json)。

已核对以下几点：

- 每个运行恰好进入一次测试折，同一折内训练与测试样本不重叠。
- 填补、缺失指示和标准化在训练折内拟合；没有发现这部分预处理泄漏。
- 模型输入只读取固定特征，路径、run_id、状态、Agent/LLM 标签不进入特征向量。
- 两个实验的数据快照哈希与配置一致，78 个原始 L3 的哈希仍一致；按当前提取器重新计算，78 个特征向量全部一致。
- 没有完全相同的原始文件或特征向量；但这不能排除同任务重复运行之间很强的相似性。
- 本次按原参数重跑交叉验证，逐样本预测与保存的评估结果完全一致。`model.joblib` 是交叉验证之后用全量数据拟合的部署模型，不是一个独立测试集上的模型。

因此，100% 不是把训练集准确率冒充测试分数；问题主要在测试分布与外推范围。

## 2. 样本覆盖存在明显缺口

[quality.json](../data/datasets/l3_v3/quality.json) 扫描了 96 个目录，只纳入 78 个：16 个因目录/manifest/L3 的 run_id 不一致被排除，另外 2 个因事件为空被排除。16 个 ID 不一致样本中还有 1 个本身没有事件。

也就是说，**15 个有交互数据的运行被元数据问题挡在训练集外**。假设其他校验均通过，修复这些 ID 后可恢复到 93 个有事件样本；剩余 3 个确实没有浏览器轨迹。本次只核查，没有修改 ID 或重建原实验。

Claude 的 8 个运行全部被排除：3 个没有事件，5 个有事件但 ID 不一致。因此 LLM 实验只识别 chat-gpt、deepseek-chat、gemini，**没有验证 Claude 的识别能力**。

| 框架 | chat-gpt | deepseek-chat | gemini | 总数 |
|---|---:|---:|---:|---:|
| Agent-E | 4 | 8 | 4 | 16 |
| AutoGen | 6 | 8 | 3 | 17 |
| Browser-use | 8 | 5 | 6 | 19 |
| Skyvern | 6 | 9 | 5 | 20 |
| WebVoyager | 6 | 0 | 0 | 6 |
| 合计 | 30 | 30 | 18 | 78 |

任务只有两个：flights 64 个、shop 14 个。shop 中 Agent-E、AutoGen、Skyvern 全部使用 DeepSeek，Browser-use 全部使用 chat-gpt；WebVoyager 只有 flights/chat-gpt。任务、框架与 LLM 因此存在强相关，分类器可能利用这些相关性。

## 3. 为什么框架识别能达到 100%

全量拟合模型中，标准化系数较大的特征包括结构按键比例、按键按住时长、鼠标按下/抬起比例的缺失指示、删除键比例、滚动反转次数、鼠标移动次数和点击坐标分散程度。系数大小仅作解释线索，不等于因果重要性；相关特征会分摊权重。

各框架的行为统计已有明显区别，例如下表为各运行特征的中位数：

| 框架 | input_count | button0_count | keypress_count | scroll_count |
|---|---:|---:|---:|---:|
| Agent-E | 78 | 0 | 95.5 | 17 |
| AutoGen | 13 | 44 | 8 | 1 |
| Browser-use | 114 | 40 | 93 | 1 |
| Skyvern | 144 | 60 | 148 | 79.5 |
| WebVoyager | 111 | 111 | 146 | 6 |

`button0_count` 是按下/抬起事件统计，不是点击次数。Agent-E 的此项为 0、点击坐标标准差为 0，但其他框架通常有这些鼠标事件。这更支持“自动化执行方式和事件形态可区分”的解释，不能直接解释为模型推理能力的差异。

补充消融实验沿用各目标原来的 5 折划分及超参数，只改变输入特征：

| 特征输入 | Agent Accuracy | LLM Accuracy |
|---|---:|---:|
| 全部特征 | 100.00% | 79.49% |
| 仅缺失/非缺失掩码 | 84.62% | 37.18% |
| 去掉时间特征 | 98.72% | 67.95% |
| 仅时间特征 | 89.74% | 70.51% |

时间特征在这里定义为名称含 `latency` 或以 `scroll_time_` 开头的字段。仅缺失模式就能识别 66/78 个框架样本，说明事件是否出现本身就是强信号；框架高分不主要依赖时间间隔。

58 个特征里有 16 个全缺失，包括全部鼠标曲率/方向统计及部分鼠标按钮比例；另外 9 个字段的非缺失值恒定。后者不能一概视为无信息，因为“有值/无值”仍可能区分类别。例如 button0_down_up_ratio 的非缺失值均为 1，但 Agent-E 的缺失本身有识别力。加入缺失指示后，保存的分类器实际接收 94 列输入。

## 4. LLM 错误集中在哪里

混淆矩阵：行为真实标签，列为预测标签。

| 真实 / 预测 | chat-gpt | deepseek-chat | gemini |
|---|---:|---:|---:|
| chat-gpt | 28 | 1 | 1 |
| deepseek-chat | 1 | 23 | 6 |
| gemini | 3 | 4 | 11 |

| 标签 | Precision | Recall | F1 |
|---|---:|---:|---:|
| chat-gpt | 87.50% | 93.33% | 90.32% |
| deepseek-chat | 82.14% | 76.67% | 79.31% |
| gemini | 61.11% | 61.11% | 61.11% |

| 所在框架 | LLM 折外正确数 | Accuracy |
|---|---:|---:|
| Agent-E | 12/16 | 75.00% |
| AutoGen | 15/17 | 88.24% |
| Browser-use | 11/19 | 57.89% |
| Skyvern | 18/20 | 90.00% |
| WebVoyager | 6/6 | 100.00% |

16 个错误中，有 8 个出现在 Browser-use：5 个 DeepSeek 航班运行全部被判成 Gemini，6 个 Gemini 航班运行中又有 3 个被判成 DeepSeek。这是具体框架内的系统性混淆。

WebVoyager 的 6/6 不足以证明模型能在该框架内区分 LLM，因为这里所有样本都是 chat-gpt。shop 14/14 也受框架与 LLM 的绑定关系影响；单看 flights 是 48/64，即 75.00%。

LLM 的五折准确率为 68.75%、93.75%、75.00%、86.67%、73.33%，波动较大。时间特征对 LLM 更有帮助，但这些间隔也可能包含工具执行、LLM 服务等待、重试及任务长度，不能全部归因于模型自身特征。

## 5. 补充泛化诊断

以下是本次额外拟合的诊断结果，使用相同的逻辑回归、C 和预处理，未调参，也未覆盖原实验。它们改变了训练/测试分布，不能与随机交叉验证当作同一测试条件。

| 检查方式 | 目标 | 正确数 | Accuracy |
|---|---|---:|---:|
| 原始按 run 分层 5 折 | Agent | 78/78 | 100.00% |
| flights 训练 → shop 测试 | Agent | 8/14 | 57.14% |
| shop 训练 → flights 测试 | Agent | 19/64 | 29.69% |
| 原始按 run 分层 5 折 | LLM | 62/78 | 79.49% |
| 整个框架留出，其他框架训练 | LLM | 28/78 | 35.90% |

- Agent 的 shop→flights 测试包含训练中没有的 WebVoyager 类；仅计算已见框架仍只有 19/58，即 32.76%。因此低分不完全由新类别导致。
- LLM 整框架留出的 Macro-F1 为 0.2706；在完全相同留出划分下，多数类基线为 26.92% Accuracy、0.1891 Macro-F1。仍有一定信号，但距稳定跨框架识别很远。
- LLM 整框架留出准确率：Agent-E 25.00%、AutoGen 47.06%、Browser-use 31.58%、Skyvern 50.00%、WebVoyager 0%。
- LLM 的 flights→shop 为 12/14（85.71%），但恰好等于始终预测 DeepSeek 的准确率，不能单凭这个数字认为任务迁移良好。
- 跨任务还混合了 LLM 覆盖差异，因此不能把下降全部归因于任务本身；这也是需要完整交叉采样的原因。

## 6. 完成情况也在影响结果

数据集保留了 5 个原始标为 failed 的运行；这是构建器的既定行为——只要轨迹可用就纳入，不把 status 当作特征。

结合之前的运行审计，78 个样本中另有 8 个实际未走完流程，全部是 Agent-E 的 DeepSeek/Gemini 运行。这会让任务长度、输入次数等与模型标签相关。按当前“流程完成即可，允许选项偏差”的口径，不能把仅仅座位、姓名、行李选错的记录一并剔除；原始 failed 也不能直接等同于实际未完成。

仅剔除这 8 个未完成流程的运行，再按同样方法做 5 折诊断：70 个样本中 Agent Accuracy=97.14%，LLM Accuracy=87.14%、Macro-F1=0.8378。样本集合和折划分已经改变，因此这只是敏感性分析，不是证明过滤能必然提升识别能力。

## 7. 下一轮实验的优先顺序

1. **修复 ID 并重新建数据集。** 先预览 `python -m agent_fingerprint normalize --input-dir data/runs/final`；修复时保留来源审计，使用新输出目录重建，避免覆盖这两份历史实验。优先恢复 15 个有轨迹的遗漏样本和 Claude 的 5 个有效样本。
2. **补齐框架 × LLM × 任务组合。** 尤其是 WebVoyager 的非 chat-gpt，以及 shop 的多模型样本；增加任务和采集批次，避免“看见框架就能猜模型”。
3. **把随机 run 划分和泛化划分分别报告。** Agent 报告跨任务、跨 LLM、跨采集批次；LLM 报告跨框架及固定框架内的分类。每种划分都配同划分下的基线。
4. **记录完成状态，分层评估。** 同时保留全轨迹和已完成轨迹的结果，检查类别之间的完成率差异，而不是直接按旧 manifest.success 筛选。
5. **继续做特征消融。** 将事件类型/计数、缺失模式、时间、几何特征分开比较。当前曲率/方向全部缺失，应先检查轨迹分段和采样是否足够，再增加复杂分类模型。

现阶段最值得保留的结论是：**框架执行方式在 L3 中留下了很强的可识别模式；LLM 区分已经有初步信号，但数据覆盖和泛化验证比更换复杂模型更需要优先解决。**
