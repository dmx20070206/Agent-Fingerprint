# final 测试逐项完成审计

[文档导航](README.md) · **历史审计**：本文保留 2026-10-04 的逐项结果，不代表当前代码的完成判定。当前用法见[采集指南](collection.md)；本地证据文件不随 Git 分发。

审计日期：2026-10-04。已记录 **96/96** 个目录。每完成一项即保存独立记录并刷新本表。

当前汇总：完美成功 **63**；假成功 **27**；不好的成功 **6**。

第 3 类中有 1 个连续验证 3 轮的案例，以及 5 个只多验证 1 次的轻度案例。为不漏掉完成后继续执行的情况，轻度案例也单列出来；若将“很多无用操作”严格限制为明显重复，则重点看 browseruse_chat_gpt_flights_5。

按用户口径，只考察完成后的冗余操作；完成前反复操作不归第 3 类。“完美成功”表示实际要求完成、未发现完成后无进展的重复操作，不代表全过程最优。首次验证、获取新证据的核验、正常总结与最终评审不算空转。对于重复相同空结果的验证，逐项给出次数，区分轻度冗余与较明显重复。

第 2 类包含 3 个原本就 failed 的 Agent-E/Claude 运行（按用户指定放置）；它们不是原始系统误报 success。其余第 2 类为原始 success 与实际完成情况不符。出现成功页面也必须核对要求的参数，例如 Carry-on=yes；优先归类实际未完成/参数错误。

最终 27 个第 2 类可分为：11 个未完成表单却记录 success，9 个漏选或取消随身行李，4 个填写错误预订参数，3 个原本就失败。另有 5 个 Browser-use/DeepSeek 的原始 failed 实际已完成，其中 3 个归第 1 类、2 个因完成后重复验证归第 3 类。

证据优先级：实际页面/工具结果与 L3 操作，高于模型最终自述和 manifest。Carry-on 的部分结论由 L3 序列重建，并非日志直接记录 checked；尤其 Browser-use/Gemini 两项标为中等置信度。页面逻辑为默认 false，点击切换，Next 保存，Back 不保存；参考 [flights.js](../sandbox/flights/js/pages/flights.js)。

数据局限：没有独立后端订单真值；当前源码用于解释历史事件，不是历史页面快照。记录中的“完成后秒数”包含模型生成、最终评审和清理，不等同于无用操作时间。shop 完成时点取首次观察到购物车与正确总价。
